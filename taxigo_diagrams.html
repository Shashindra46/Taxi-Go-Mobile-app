Diagram 03
Sequence Diagram — Deferred signUp Auth Architecture
Why auth.signUp() is called at Step 3 (document upload), not Step 1 — so the 8-digit OTP email arrives moments before the driver sees the OTP input screen.
sequenceDiagram
    autonumber
    participant U  as 🧑 Driver
    participant F  as 📱 Flutter App
    participant SB as 🔐 Supabase Auth
    participant DB as 🗄️ Supabase DB
    participant ST as 📦 Supabase Storage
    participant EM as 📧 Resend Email

    Note over U,F: STEP 1 — Personal Info
    U->>F: Fill name, phone, NIC, email, password
    F->>F: Validate form only — NO Supabase call
    F->>U: Navigate to Step 2

    Note over U,F: STEP 2 — Vehicle Details
    U->>F: Fill vehicle type, brand, model, plate, year
    F->>F: Carry all data in route arguments
    F->>U: Navigate to Step 3

    Note over U,F: STEP 3 — Document Upload + SUBMIT
    U->>F: Upload 4 documents
    U->>F: Tap Submit

    F->>SB: auth.signUp(email, password)
    SB-->>EM: Dispatch 8-digit OTP email via Resend SMTP
    SB-->>F: { user: { id: "uuid-..." } }

    F->>DB: INSERT INTO drivers (user_id, name, phone, nic, status)
    DB-->>F: { id: "driver-uuid" }

    F->>DB: INSERT INTO vehicles (driver_id, type, brand, model, plate...)
    DB-->>F: { id: "vehicle-uuid" }

    F->>ST: Upload license_front.jpg
    F->>ST: Upload license_back.jpg
    F->>ST: Upload nic.jpg
    F->>ST: Upload revenue_license.jpg
    ST-->>F: Public URLs returned

    F->>U: Show success dialog → Navigate to OTP Screen

    Note over U,EM: OTP arrives in inbox at this moment ✓

    Note over U,F: STEP 4 — OTP Verification
    U->>F: Enter 8-digit code from email
    F->>SB: auth.verifyOTP(email, token, type: signup)
    SB-->>F: Session confirmed ✓
    F->>U: Navigate to Login screen
signUp deferred to Step 3 — token always fresh
OTP type must be OtpType.signup
Resend SMTP bypasses Supabase rate limit

Diagram 04
State Machine — Ride Lifecycle
Every possible state of the rides.status column, and the exact app action that triggers each transition, streamed live via Supabase Realtime.
stateDiagram-v2
    direction LR

    [*] --> pending       : 📍 Customer books ride\n(INSERT into rides)

    pending --> accepted  : 🚗 Driver taps Accept\n(UPDATE status + driver_id)
    pending --> cancelled : ❌ Customer cancels\n(UPDATE status)

    accepted --> arrived  : 📌 Driver taps Arrived\n(UPDATE status)

    arrived --> in_progress : 🚦 Driver taps Start Trip\n(UPDATE status)

    in_progress --> completed : 🏁 Driver taps Complete\n(UPDATE status, stop GPS)

    completed --> paid_cash  : 💵 Customer selects Cash\n+ Driver confirms receipt\n(UPDATE payment_method + payment_status)
    completed --> paid_card  : 💳 Customer selects Card\n(UPDATE payment_method + payment_status)

    paid_cash --> rated      : ⭐ Customer rates driver
    paid_card --> rated      : ⭐ Customer rates driver

    rated     --> [*]
    cancelled --> [*]
